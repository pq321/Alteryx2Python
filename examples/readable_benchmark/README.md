# Readable Python Benchmark

comprehensive.yxwz is the connected analytic app. NormalizeMeasurements.yxmc
and BenchmarkParallelBlock.yxmc are original local macros. The data directory
contains the pinned public Iris source and provenance. before.bat and after.bat
are benign events that write markers in their configured working directory.

acceptance/phase_one.py preserves the baseline graph. acceptance/readable.py
is the editable standalone result. Its run_workflow function shows the explicit
pipeline. Sidecars preserve source mappings, template hashes and IR.
acceptance/acceptance.json records exact node and artifact comparisons.

This example is regenerated by the common compiler. Native templates resolve
configuration at compile time; dependency boundaries determine stage functions.
Checkpoint instrumentation is confined to a separate verification build. The
acceptance runner executes the delivered source independently as well.

Regenerate into a fresh directory with commands in
[the migration guide](../../docs/readable_python.md). The acceptance runner
isolates outputs and command/event working directories. Manually executing
the standalone benchmark requires allowlisting the two batch scripts and the
Python executable preserved in its Run Command configuration.

Run the checked-in standalone program from the repository root:

~~~powershell
$sample = (Resolve-Path examples/readable_benchmark).Path
$python = (Resolve-Path .venv/Scripts/python.exe).Path
$output = Join-Path (Get-Location).Path 'reports/try-readable'
$workflowArgs = @(
    "$sample/acceptance/readable.py",
    '--input-dir', $sample,
    '--output-dir', $output,
    '--event-working-dir', $output,
    '--command-working-dir', $output,
    '--allow-command', $python,
    '--allow-command', "$sample/before.bat",
    '--allow-command', "$sample/after.bat",
    '--minimum-sepal-length', '6.5'
)
& $python @workflowArgs
~~~

Email output is a local .eml draft. No mail is sent. Native engine acceptance
is blocked by the installed EngineCmd license; native-probe.json contains the
process result. Full inventory and unimplemented cases are recorded separately
in coverage/coverage.json.
